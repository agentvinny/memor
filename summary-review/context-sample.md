# Workspace session history — /home/adlokib/workspace/projects/memory

How to read this document — a compression ladder over this workspace's raw session logs (each level folds the sibling summaries of the level below it):
  L1 = one work window (≈N tool calls, one paragraph) → L2 → L3 → …
  A  Apex: the current tree's apex, i.e. the deepest fold that exists so far (it grows as the tree folds upward), in as few lines as possible (orientation).
  B  Mid series: L3 nodes — the whole project at mid grain (that level is computed as L-Max − 2 from the live tree; it holds 9-18 nodes once the tree is steady); nodes already folded into A appear here again at finer grain, by design.
  C  Newer than B: work not yet folded into A/B, plus always the last 6 L1 windows (the latest thing that was happening, at full detail).
  D  Raw tail: events after the last flushed window, one representative line per event — user messages whole (harness reminders as a one-line note), calls with the field that says what they did, results by status and first line; not yet summarized (a flush worker is digesting them).
  Coverage: a summary whose span falls inside a LISTED higher summary's fold is not re-listed — a detail missing at a lower level is already inside the higher entry. Nodes marked 'uncovered' are the opposite: newer than every higher entry shown.
  Every entry describes its own window, including what was open then: later entries record the resolution. Current state = the newest entries + D.
  Every entry is prefixed by the seq range it covers — its own window for L1s, the union of its leaf windows for folds (e.g. 1234..1301) — and is one clean paragraph (summarizer formatting like bold/lists dropped; nothing elided).
  Drill down: `memor span "dsh:<session>:seq[1234..1301]"` shows the raw window; `memor summaries --tree --workspace /home/adlokib/workspace/projects/memory` shows the whole tree; MCP: memory_get_span / memory_drill_down.
